00 — Como apresentar

Roteiro de apresentação: do objetivo ao código

Esta é a sequência recomendada para explicar a visualização ao professor. A ideia é começar pelo porquê da visualização, depois explicar o que está sendo mostrado, demonstrar como o usuário interage e só então entrar nos detalhes de como foi implementada.

1. Objetivo→ 2. Dados→ 3. Interação→ 4. Implementação

1. Comece pelo objetivo da visualização

Primeiro explique qual pergunta ou relação a visualização ajuda o usuário a entender. Não comece falando de Canvas, SVG ou D3.js.

O que você pode falar:
"Essa visualização tem como objetivo analisar a relação entre o preço dos jogos e o tempo médio que os jogadores passam jogando."

2. Explique os dados

Depois apresente o significado visual dos dados: o que representa cada ponto, o que aparece nos eixos e como as cores são utilizadas.

O que você pode falar:
"Cada ponto representa um jogo. No eixo X temos o preço do jogo e no eixo Y temos o tempo médio de jogo, convertido de minutos para horas. As cores representam o gênero principal do jogo."

Você pode complementar explicando que os dados passam por um tratamento inicial, no qual o módulo mantém registros com preço definido, tempo de jogo válido e pelo menos um gênero.

3. Mostre a interação

Agora demonstre o que o usuário consegue fazer com a visualização. Essa é uma boa hora para mostrar a aplicação funcionando na tela.

O que você pode falar:
"O usuário pode pesquisar um jogo pelo nome, limitar o preço máximo usando o slider, aplicar filtros globais de ano e gênero, utilizar o zoom e clicar em um jogo para visualizar seus detalhes no painel."

4. Só depois entre na implementação

Depois que o professor já entendeu o objetivo, os dados e as interações, explique como o sistema foi construído.

O que você pode falar:
"Para implementar essa visualização, utilizamos Canvas para desenhar os pontos e SVG para os eixos. O D3.js é utilizado para criar as escalas, eixos, zoom e escala de cores. O módulo também se comunica com o Coord, que permite compartilhar filtros e seleções entre as visualizações."

5. Aprofunde no código

Se o professor quiser saber como o código funciona, siga uma ordem lógica:

Dados brutos→ filter()→ map()→ Escalas→ Canvas + SVG→ Filtros→ render()→ Interação→ Coord
Roteiro completo para falar:

"Essa visualização tem como objetivo analisar a relação entre o preço dos jogos e o tempo médio de jogo. Cada ponto representa um jogo, sendo que o eixo X mostra o preço e o eixo Y mostra o tempo médio de jogo em horas. A cor representa o gênero principal.

Além disso, o usuário pode interagir com a visualização por meio de filtros, busca por nome, limite de preço, zoom e seleção de jogos. Ao clicar em um ponto, os detalhes daquele jogo são apresentados no painel.

Tecnicamente, os dados são inicialmente filtrados e transformados para o formato utilizado pelo módulo. A visualização utiliza Canvas para desenhar os pontos e SVG para os eixos. O D3.js é responsável pelas escalas, eixos, zoom e cores. A função render() combina os filtros globais e locais e redesenha os pontos. A comunicação com o Coord permite que as alterações de estado sejam refletidas entre as visualizações."
Dica para a apresentação:
Pense nesta ordem: Por quê? → O quê? → Como o usuário usa? → Como foi implementado?. Se o professor interromper com uma pergunta técnica durante a explicação, responda e depois retome o ponto em que estava.
01 — Visão geral

O que esse código faz?

O módulo VizPrecoTempo cria e controla uma visualização que relaciona preço e tempo médio de jogo. Cada jogo é representado por um ponto.

Dados brutos→ Filtragem e transformação→ Escalas→ Canvas + SVG→ Filtros e interação
Como falar para o professor:
"Esse módulo recebe os dados brutos dos jogos, seleciona os registros que possuem informações válidas de preço, tempo e gênero, transforma o tempo de minutos para horas e cria uma visualização de dispersão. O eixo X representa o preço, o eixo Y representa o tempo médio de jogo e as cores representam o primeiro gênero do jogo. A visualização ainda possui filtros, zoom e seleção de pontos."
02 — Estrutura

IIFE e módulo revelador

var VizPrecoTempo = (function(){
  // Todo o estado abaixo fica encapsulado dentro da função
  ...
  return { init: init };
})();

A função é executada imediatamente. O resultado é armazenado em VizPrecoTempo. Como as variáveis e funções ficam dentro dessa função, elas não ficam diretamente expostas no escopo global.

IIFE
Função que é definida e executada imediatamente.
Encapsulamento
Variáveis como estado, xScale e render ficam privadas.
API pública
O objeto retornado expõe somente init.
Professor pode perguntar:
"Por que usar IIFE?"

Resposta: "Para encapsular o estado e as funções internas do módulo, evitando que esses nomes fiquem disponíveis globalmente e reduzindo possíveis conflitos com outros módulos."
03 — Inicialização

Função init(dadosBrutos)

A função init é o ponto de entrada público do módulo. Ela recebe os dados brutos e prepara praticamente toda a visualização. 

function init(dadosBrutos){
  dadosModulo = dadosBrutos
    .filter(function(d){
      return d.price !== undefined &&
             d.average_playtime_forever > 0 &&
             d.average_playtime_forever < 50000 &&
             d.genres && d.genres.length > 0;
    })
    .map(function(d){
      return { ... };
    });
}

Primeiro passo: filtrar

O código elimina jogos que não possuem preço, possuem tempo de jogo inválido, possuem tempo acima de 50.000 minutos ou não possuem gênero.

Segundo passo: transformar

O map() cria um novo objeto simplificado para o módulo, mantendo apenas os campos necessários para a visualização e para o painel de detalhes.

Como explicar:
"Primeiro eu faço uma limpeza dos dados. Depois transformo os registros para um formato mais adequado ao módulo. Isso facilita o uso dos dados durante a renderização e mantém no módulo apenas as informações relevantes."
Ponto para prestar atenção:
O código usa d.genres[0] como genero, mas mantém todos os gêneros em generos. Portanto, a cor e o filtro de gênero consideram apenas o primeiro gênero, enquanto o painel pode mostrar todos.

05 — Renderização

Por que Canvas + SVG?

function montarCanvas(){
  ...
  canvas = d3.select("#pt-chartWrap").append("canvas")
  ...
  svg = d3.select("#pt-chartWrap").append("svg")
}

O código cria duas camadas. O Canvas é usado para desenhar os pontos. O SVG é usado para os eixos.

Canvas

Usado para desenhar os pontos diretamente no contexto 2D.

SVG

Usado para os eixos, aproveitando os recursos do D3 para gerar e atualizar os eixos.

Professor: "Por que não desenhar tudo em SVG?"

Resposta: "A escolha foi separar as responsabilidades: os pontos são desenhados no Canvas, enquanto os eixos ficam em SVG. Isso evita criar um elemento DOM individual para cada ponto e mantém os eixos fáceis de manipular com o D3."

devicePixelRatio

O código usa window.devicePixelRatio para ajustar a resolução interna do Canvas. Depois utiliza ctx.scale(dpr, dpr).

Como explicar:
"O devicePixelRatio ajuda a adequar a resolução interna do Canvas à densidade de pixels da tela, evitando que o desenho fique visualmente borrado em telas de alta densidade."
06 — Escalas

xScale e yScale

xScale = d3.scaleLinear()
  .domain([-1, d3.max(dadosModulo, function(d){ return d.price; }) + 5])
  .range([margin.left, width - margin.right]);

yScale = d3.scaleLinear()
  .domain([0, d3.max(dadosModulo, function(d){ return d.horas; }) + 20])
  .range([height - margin.bottom, margin.top]);

A escala converte valores dos dados para coordenadas na tela.

EscalaDadosTela
xScalePreçoPosição horizontal
yScaleHorasPosição vertical
Professor pode perguntar: "Por que o range do Y está invertido?"

Resposta: "Porque no sistema de coordenadas da tela o eixo Y cresce de cima para baixo. Então valores maiores precisam ser posicionados mais acima no gráfico, por isso o range começa em height - margin.bottom e termina em margin.top."
07 — Interação

Zoom

function ativarZoom(){
  var zoom = d3.zoom()
    .scaleExtent([0.5, 20])
    .on("zoom", function(e){
      zoomTransform = e.transform;
      desenharEixos(zoomTransform.rescaleX(xScale), zoomTransform.rescaleY(yScale));
      desenharPontos();
    });
  canvas.call(zoom);
}

O zoom permite alterar a transformação aplicada à visualização. Quando ocorre um evento de zoom, o código atualiza as escalas dos eixos e redesenha os pontos.

Como explicar:
"O D3 controla a transformação do zoom. A cada interação, eu pego a transformação atual, recalculo as escalas usando rescaleX e rescaleY, atualizo os eixos e redesenho os pontos para que tudo permaneça sincronizado."
Ponto de atenção:
O código limita apenas a escala do zoom com scaleExtent([0.5,20]). Não existe translateExtent, então o deslocamento pode permitir que o usuário navegue para regiões sem dados.
08 — Filtros

Filtros globais e locais

function passaFiltrosGlobais(d, coordState){
  if (d.year < coordState.anoMin || d.year > coordState.anoMax) return false;
  if (coordState.genero && d.genero !== coordState.genero) return false;
  return true;
}

function passaFiltrosLocais(d){
  if (estado.busca && d.name.toLowerCase().indexOf(estado.busca) === -1) return false;
  return d.price <= estado.precoMax;
}
Global

Ano e gênero vêm do estado compartilhado em Coord.

Local

Busca pelo nome e preço máximo pertencem ao próprio módulo.

Como explicar:
"Um jogo precisa passar pelos filtros globais e pelos filtros locais. O operador lógico utilizado na função render é AND, então basta falhar em um dos grupos para deixar de ser considerado visível."
09 — Renderização

O papel da função render()

function render(){
  var coordState = Coord.getState();
  visiveis = dadosModulo.filter(function(d){
    return passaFiltrosGlobais(d, coordState) && passaFiltrosLocais(d);
  });
  ...
  desenharPontos();
}

A função render é responsável por recalcular quais jogos estão visíveis e solicitar o redesenho.

Estado atual→ Aplicar filtros→ Atualizar visiveis→ Atualizar estatística→ Desenhar pontos
Professor: "Quando render é chamado?"

Resposta: "Ele é chamado na inicialização e também quando ocorre alguma alteração relevante nos filtros locais, como busca e preço, ou quando o estado global coordenado muda."
10 — Canvas

Como os pontos são desenhados?

O código primeiro limpa o Canvas, cria uma área de recorte e depois desenha os pontos em diferentes níveis de opacidade.

1. Pontos fora do filtro local

Continuam visíveis, mas com opacidade 0.05 e cor cinza. Isso preserva o contexto.

2. Pontos visíveis

São desenhados com opacidade 0.75 e cor baseada no gênero.

3. Jogo selecionado

É desenhado por último, maior e com borda branca.

Como explicar:
"A ideia de desenhar os pontos filtrados com baixa opacidade é preservar o contexto espacial. Assim, o usuário consegue perceber onde os dados filtrados estavam no conjunto original."
Detalhe importante:
O jogo selecionado é procurado em dadosModulo, não em visiveis. Portanto, ele pode continuar destacado mesmo depois que um filtro o exclui da lista de visíveis. Essa é uma decisão/comportamento que você deve saber explicar se o professor questionar.

Como Canvas não possui um elemento DOM separado para cada ponto, o código precisa calcular manualmente qual ponto está próximo da posição clicada.

Como explicar:
"Eu converto a posição do clique para coordenadas relativas ao Canvas e percorro os pontos visíveis. Para cada ponto calculo a distância euclidiana até o cursor. Se a distância for menor que o raio de clique de 10 pixels, considero aquele jogo como candidato."
Pergunta avançada: "Qual é a complexidade?"

Resposta: "A busca percorre todos os pontos visíveis, então no pior caso é O(n). Como isso ocorre no clique e não continuamente durante a animação, o custo é aceitável para o volume atual de dados. Para datasets muito maiores, poderia ser necessário utilizar uma estrutura espacial ou outra estratégia de busca."
12 — Coordenação

Como o Coord conecta as visualizações?

Coord.on(function(coordState){
  atualizarBadgeGenero(coordState.genero);
  atualizarDestaqueLegenda(coordState.genero);
  render();
  atualizarPainel(coordState.jogoSelecionado);
});

O módulo se inscreve no Coord. Quando o estado compartilhado muda, o callback é executado.

Usuário interage→ Coord altera estado→ Listeners são notificados→ VizPrecoTempo atualiza
Como explicar:
"O Coord funciona como um ponto central de coordenação. O módulo não precisa conhecer diretamente os outros módulos. Ele reage às mudanças do estado compartilhado por meio do mecanismo de inscrição."
13 — Detalhes

Como funciona o painel do jogo selecionado?

A função atualizarPainel(jogoId) recebe o identificador do jogo selecionado, procura esse jogo em dadosModulo e atualiza o conteúdo do painel.

Se nenhum jogo estiver selecionado, aparece uma mensagem orientando o usuário a clicar em um ponto. Se o ID não for encontrado, aparece uma mensagem informando que o jogo não possui dados suficientes.

Quando o jogo existe, o painel mostra imagem, nome, preço, tempo médio, gêneros, desenvolvedora e recomendações.

Como explicar:
"A seleção no gráfico não serve apenas para destacar o ponto. Ela também atualiza um painel de detalhes. O ID do jogo funciona como a ligação entre a seleção visual e as informações detalhadas do registro."
14 — Resumo

Fluxo completo para memorizar

init(dadosBrutos)→ filter()→ map()→ montarCanvas()→ criar escalas→ eixos→ zoom→ render()

Durante a interação

Filtro local→ estado muda→ render()→ visiveis é recalculado→ Canvas redesenhado

Durante a coordenação global

Outro módulo altera Coord→ Coord notifica→ VizPrecoTempo recebe coordState→ render + painel + legenda
Resposta de 1 minuto:
"O módulo começa recebendo os dados brutos e fazendo uma filtragem inicial. Depois transforma os registros para um formato adequado, cria o Canvas para os pontos e o SVG para os eixos. As escalas convertem preço e horas em coordenadas de tela. A função render combina os filtros globais, vindos do Coord, com os filtros locais do próprio módulo. Os pontos são então desenhados no Canvas. O usuário pode aplicar filtros, usar zoom e clicar em pontos. Quando existe uma seleção, o jogo é destacado e seus detalhes aparecem no painel. O Coord permite que mudanças de estado sejam compartilhadas entre as visualizações."
15 — Treino

Perguntas que você deve saber responder

1. O que cada ponto representa?

Um jogo presente nos dados tratados pelo módulo.

2. O que X representa?

O preço do jogo.

3. O que Y representa?

O tempo médio de jogo convertido de minutos para horas.

4. Por que Canvas?

Para desenhar os pontos sem criar um elemento DOM individual para cada ponto.

5. Por que SVG?

Para os eixos, que são gerenciados facilmente pelo D3.

6. Como funciona o filtro?

Filtros globais e locais precisam ser satisfeitos para o jogo entrar em visiveis.

7. Como o clique encontra o jogo?

Calculando a distância entre o cursor e cada ponto visível.

8. Qual a complexidade?

A busca pelo ponto no clique é O(n) no pior caso.

9. O que é Coord?

É o mecanismo utilizado para compartilhar estado e notificar os módulos inscritos.

10. O que você melhoraria?

Limitar o deslocamento do zoom, considerar datasets maiores e revisar o tratamento de muitos gêneros.
